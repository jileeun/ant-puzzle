# 밸런스 테이블 구조

실제 값: `balance/balance.js` (`window.BALANCE`) · 기획 의도: [GDD.md](GDD.md)
게임 코드(`index.html`)는 `stageBalance(i)`로 아래 순서대로 값을 합쳐 스테이지 i에 적용한다.

```
최종값 = curve(스테이지 번호)  +  tiers[등급] 가감  →  stages[n] 덮어쓰기
등급   = stages[n].tier  ||  pattern 중 처음 맞는 규칙
```

## 1. `curve` — 기본 난이도 곡선
| 키 | 형태 | 뜻 |
|---|---|---|
| `noLinkUntil` | 정수 | 이 번호(0부터) 미만 스테이지는 사슬 0 |
| `link` | `{base, perStage, max}` | 줄마다 사슬이 생길 확률 |
| `jitter` | `{base, perStage, max}` | 쇠똥구리 순서를 뒤섞을 확률 |
| `ants` | `{base, perStage, max}` | 목표 쇠똥구리 수 |
값 = `min(max, base + perStage × i)`

## 2. `tiers` — 난이도 등급 (허들)
| 키 | 뜻 |
|---|---|
| `label`, `color` | 메뉴 태그·배너 표시 |
| `slots` | 쓸 수 있는 일터 칸 (나머지는 잠김, 🔓 열쇠로 열림). 스테이지 생성 시뮬도 이 칸 수로 돌아감 |
| `linkAdd`, `jitterAdd` | 곡선 값에 더함 (0~0.9로 자름) |
| `jitterSpan` | 순서를 바꿀 때 최대 몇 칸 멀리까지 바꾸는지 |
| `antMul` | 목표 쇠똥구리 수 배율 |
| `qa.randomFail`, `qa.greedyFail` | QA 목표 구간 `[최소, 최대]` |
| `qa.solvable` | 반드시 풀 수 있어야 함 |

## 3. `pattern` — 허들 배치 규칙
`{ when: 'JS 식 (n = 1부터 스테이지 번호)', tier }` 배열. 위에서부터 처음 맞는 규칙.

## 3-1. `gimmicks` / `gimmickRules` — 기믹 (허들의 재미 요소)
`gimmicks.<키>` 는 소개 창·안내에 쓰는 정의: `icon`, `name`, `color`, `desc[2줄]`, `tip`. (`gift.rewards` = 선물로 나올 수 있는 부스터 목록)
코드가 아는 키: `key`(🔑), `ice`(🧊), `colLock`(⛓), `gift`(🎁). 첫 등장 스테이지는 규칙에서 자동 계산해서 소개 창을 띄움.

`gimmickRules`: `{ when: 'JS 식 (n)', set: {...} }` — **맞는 규칙을 모두** 위에서부터 합침 (아래가 덮어씀). 결과는 `stages[n].gimmicks` 로 다시 덮어쓸 수 있음.
| `set` 키 | 형태 | 뜻 |
|---|---|---|
| `lockSlots` | 정수 | 잠긴 일터 칸 수 (오른쪽부터). 🔑 하나에 한 칸 |
| `lockCols` | 0/1 | 오른쪽 대기열 줄 잠금. 일터 자물쇠 다음 순서로 🔑이 엶 |
| `keyAt` | `[비율…]` | 자물쇠마다 🔑을 숨길 위치 = 1차 시뮬에서 음식이 먹히는 순서의 몇 % 지점 (작을수록 빨리 열림) |
| `ice` | 비율 | 얼음 음식 비율 (전체 음식 대비) |
| `giftAt` | `[비율…]` | 🎁 위치 (개수만큼) |

## 4. `stages` — 스테이지별 덮어쓰기 (키 = 스테이지 번호, 1부터)
`tier`, `slots`, `link`, `jitter`, `jitterSpan`, `ants`, `seed`, `reward`, `gimmicks` 중 필요한 것만.
- `seed`: 쇠똥구리 순서 난수 번호. **QA가 목표 구간에 맞는 값을 골라 고정.**
- `reward`: `{ 부스터키: 개수 }` — 처음 클리어 선물 (규칙보다 우선)

## 5. `boosters` / `boosterOrder` / `startInventory` / `maxPerBooster`
| 키 | 뜻 |
|---|---|
| `boosters.<키>` | `icon`, `name`, `color`, `desc[2줄]`, `rescue`(실패 화면에 뜨는지 참고용) |
| `boosterOrder` | 가방·실패 화면 표시 순서. 코드가 아는 키: `undo`, `key`, `unchain`, `bomb` |
| `startInventory` | 처음 시작 시 지급 |
| `maxPerBooster` | 종류별 보관 상한 |

## 6. `rewards` — 클리어 선물 규칙 (처음 깰 때만)
| 키 | 뜻 |
|---|---|
| `beforeBoss` | 다음 스테이지가 보스인 스테이지를 깨면 |
| `bossCycle` | 보스를 깰 때마다 차례대로 |
우선순위: `stages[n].reward` → `beforeBoss` → `bossCycle`

## 7. `hiddenItems` — 숨은 아이템 (모드별)
`{ count, perStage, max, types }` — 개수 = `min(max, count + floor(i × perStage))`. 혼자·협동은 0 (부스터로 대체), 경쟁만 사용.
